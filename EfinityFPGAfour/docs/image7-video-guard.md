# image7 MIPI 时序裕量实验候选

用途：针对原image7“实时画面闪烁、上下重复，30秒504帧全部未通过完整性检查”，提供只改变MIPI时序约束的候选位流。原image6同硬件20秒1,200帧全部完整，正常访问DDR。原image6和原image7发布包保留。

本候选不是已确认修复版。额外MIPI建立裕量0.500 ns、保持裕量0.300 ns为工程实验值，并非板上抖动实测值。模型权重、RTL、时钟频率、引脚、DPHY delay=17和FT232H协议均不改变。具体依据与限制见同包诊断记录。

完整构建通过28项setup/hold关系，CDC无警告。资源XLR54,919/60,800、RAM185/256、DSP75/160。报告中CSI建立不确定度0.610 ns、保持不确定度0.370 ns，分别包含新增0.500/0.300 ns裕量；裕量扣除后CSI建立slack1.913 ns、保持slack0.009 ns，系统建立slack0.252 ns。位流SHA256为 `d5656cf07aa8bf09583f5f84ccbd006f38e8f8a47ad43b2457d4cbfe548bf8af`。这些是工具检查结果，尚未通过此候选的实板验证。

## 首次隔离验证

1. 保持当前接线和SD卡文件不变，暂时不要复制MODEL7.BIN，以维持与原image7故障测试相同的启动条件。
2. 临时JTAG下载此候选包中的 `fpga/image7_mocap11_a.bit`，不写Flash。
3. 保持COM32接到运行工程的电脑，关闭串口助手，反馈实时画面是否完整稳定。代理将使用现有 `~6D` 读取完整帧、坏帧、缓存切换和显示欠载计数。
4. 未复制MODEL7.BIN时，ERR04仍是预期的文件缺失状态；它与这次视频隔离验证分开处理。

## 视频确认后的模型验证

视频和完整帧计数恢复后，再将同包 `sdcard/MODEL7.BIN`（236,448字节）复制到2 GB FAT32卡根目录。原MODEL6.BIN可保留。重新临时下载候选位流，观察LOAD→TEST→RDY及十一点骨架。

无需PC运行模型。串口命令、数据包格式、模型身份与原image7一致，兼容命令仍为 `~6S/~6F/~6V/~6-/~6+/~6R/~6H/~6D`。详细说明见包内原image7使用说明。实际帧率仍未验收，15 fps尚未达成。
