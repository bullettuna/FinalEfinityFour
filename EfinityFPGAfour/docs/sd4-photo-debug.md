# SD 4-bit 初始化和拍照保存

当前这些功能在镜像 2 中启用：`images/image2_photo/Ti60_Image2_Photo.xml`。
镜像 1 和原兼容工程的默认配置不启用 TF/拍照/相册，i/b/x 等返回 !。
请先阅读 [两个镜像的下载与测试说明](dual-images.md)。

工程 `E:\Efinity_Project\EfinityFPGAfour` 使用一个原生 SD 控制器。
`i` 初始化/检查、`b` 保存和相册读取共用同一套卡状态，不使用 SPI 初始化。

## 上板顺序

1. 用 JTAG 下载镜像 2 的 `outflow/Ti60_Image2_Photo_checked.bit`。
2. 如果此前运行过 SPI 工程，让 TF 卡真正断电后重新上电，再使用新工程。
3. 发送小写 `i`。成功时只收到一条 `TF:INIT_OK`。
4. 使用 FAT32 卡发送小写 `b`。整帧 DDR 写入成功后收到 `DDR_OK`；
   BMP 数据、FAT 和目录项全部写入成功后收到 `tfOK`。
   文件位于根目录，名称为 `IMG00001.BMP`，后续编号递增。

`i` 不检查文件系统。SDSC 卡也可能使用 FAT16，因此 `i` 成功不代表文件系统
适合当前 FAT32 保存算法。本工程不会自动格式化卡。

## 本次修正

- 命令或回复结束后保留至少 8 个 SD 时钟周期的空闲间隔，之后才通知上层继续。
- CMD8 无回复或明确返回非法命令时进入旧 SDSC 兼容流程；CRC/帧错误单独报错。
- ACMD41 保留电压窗口检查、HCS/CCS 判断，并增加从第一次 ACMD41 开始的
  1 秒等待期限。仍有重试次数上限作为额外保护。
- 校验 CSD 结构和容量；SDSC 使用 CMD16 设置 512 字节块长度，读写参数为字节地址。
- 已初始化时再次发送 `i`，使用 CMD13 检查 READY_FOR_DATA 和 TRAN 状态。
- 初始化失败返回命令编号和原因。命令编号为两位十进制，前导零属于正常显示。

例如：

```text
TF:INIT_FAIL CMD=55 ERR=TIMEOUT
TF:INIT_FAIL CMD=09 ERR=CRC
TF:INIT_FAIL CMD=07 ERR=BUSY_TIMEOUT
```

每次失败只发送一条消息。之后再次发送 `i` 可重新尝试初始化。

## 错误原因

- `TIMEOUT`：等待 CMD 回复超时；检查卡模式、电源和 CMD 双向通信。
- `CRC`：CMD 回复 CRC7 错误。
- `FRAME`：回复命令编号、帧头或结束位错误。
- `STATUS`：卡返回错误状态、无有效 RCA、缺少 APP_CMD 或未处于可传输状态。
- `ECHO`：CMD8 返回的电压/检查模式不符合 `0x1AA`。
- `INIT_TIMEOUT`：ACMD41 一直未就绪，达到时间或重试上限。
- `BUSY_TIMEOUT`：CMD7 选卡后 DAT0 长时间不释放。
- `CSD`：不支持的 CSD 结构、无效容量或 CSD 与 CCS 不一致。
- `VOLTAGE`：OCR 中没有支持当前主机电压的窗口。
- `DATA_CRC`：读出的扇区 CRC16 错误。
- `DATA_TOKEN`：卡拒绝写入数据包。
- `DATA_TIMEOUT`：扇区数据或写忙状态超时。
- `ADDRESS`：SDSC 的扇区到字节地址转换会溢出。

保存阶段的文件系统错误仍使用 `TF_FAIL:XX`（XX 为两位十六进制）。
`01` 是卡初始化失败，`09` 是卡读写失败，这两类现在也附带 `CMD` 和 `ERR`。
`03` 表示不符合保存器支持的 FAT32 格式。

## DDR 缓冲

960×540 RGB565 使用 `0x01600000` 和 `0x01700000` 两块独立缓冲。
上一张成功保存的照片，在下一张完整写入 DDR 后才释放其缓冲所有权。
释放是允许后续覆盖，不是擦除整块 DDR。
保存失败保留当前照片，再次发送 `b` 会重试保存同一张照片。

## DDR 共享访问与 BUSY 诊断

照片读取分成四次 128 字节 AXI 突发。收到每次突发时持续接收数据，
完整缓存 512 字节之后才逐字节送给保存器，发送字节时不占用 DDR 读事务。
显示 FIFO 接近空时，视频读请求优先于照片读请求。

仲裁器在客户端握手时锁存地址和长度，并保持对 DDR 的 VALID 直到握手完成。
视频换帧后，已经在途的旧视频数据会被排空并丢弃，不写入新帧显示 FIFO。

保存期间发送 `i` 或再次发送 `b` 不会启动另一个事务，会返回一次状态快照，例如：

```text
BUSY ST=DDR_READ RD=2 B=08/32 AXI=2
```

重复状态查询在发送队列拥挤时会被忽略，为已接受事务的完成、错误和故障回执
预留四个队列位置，避免频繁发送 `i`/`b` 挤掉 `tfOK` 或失败消息。

- `ST`：CAPTURE 拍摄、SD_INIT 检查卡、DDR_READ 读取照片、SD_READ/SD_WRITE
  卡读写、DIR_SCAN 目录扫描、FAT_SCAN 分配簇、META 整理文件信息、RECOVER 排空迟到事务。
- `RD`：照片 DMA 状态。0 空闲，1 地址等待，2 数据等待，3/4 缓存字节输出，
  5 等待迟到地址握手，6 排空迟到数据，7 输出完成，8 恢复期限已过。
- `B`：当前 512 字节扇区已收到的 128 位字数，总计 32。
- `AXI`：共享读仲裁器状态。0 空闲，1 等待 DDR 地址握手，2 等待数据，3 超过期望拍数仍未收到 RLAST。

默认 DDR 无进度等待期限为 50ms；报告失败后继续保持合法的 VALID/RREADY，
排空已发出的事务。恢复期间拒绝新保存请求，避免迟到数据混入下一张照片。
照片数据/文件系统信息没有继续发布，失败照片仍在 DDR 中。

错误回执包括：

```text
TF_FAIL:DDR_ADDR_TIMEOUT
TF_FAIL:DDR_DATA_TIMEOUT
TF_FAIL:DDR_RLAST
TF_FAIL:DDR_RESPONSE
TF_FAIL:DDR_FRAME
TF_FAIL:SAVE_TIMEOUT ST=1C
FAULT:RESET_REQUIRED AXI=2 RD=8
```

每个错误事件只主动报告一次，故障期间再发送命令则查询当前故障。
`SAVE_TIMEOUT ST` 是保存器失败前的状态编号（十六进制），例如 01 等待卡初始化、
0B 等待 DDR 数据、1C 等待卡扇区完成。保存器按单次等待是否有进展计时，
不会因为整张卡扫描或正常大文件保存耗时较长而直接超时。

如果迟到的事务完整结束，控制器恢复到可重试状态；再发 `b` 保存保留的照片。
如果底层一直不返回地址响应或最后一拍，恢复期限后明确报告 RESET_REQUIRED，
此时需要系统复位。代码不会在事务仍在途时直接释放仲裁归属。


视频测试使用行为 FIFO 和 DDR 存储模型；物理 DDR 和 HDMI 引脚仍需上板验证。

## 相册读取和绿色花屏修正

保存成功后发送 `x`（或 `X`）进入相册；`<` 上一张，`>` 下一张。
首尾循环翻页，再次发送 `x` 退出；重新进入从编号最小的照片开始。
请等待本次加载结束再翻页。初始化 `i` 和拍照保存 `b` 的 SD 原生协议未改变。

相册增加一次性回执：

```text
ALBUM:READY
ALBUM:FAIL
ALBUM:DISPLAY_FAIL
ALBUM:EXIT
```

`READY` 表示读卡完成、整张照片的 DDR 写响应成功，并已在垂直消隐期发布
显示缓冲。`FAIL` 表示读卡、文件解析或 DDR 装载失败，不发布残缺照片。
`DISPLAY_FAIL` 表示显示 FIFO 数据不足；本帧剩余区域清黑，下帧重新同步，
同一次装载不会逐帧重复报告。退出在加载完成后使用 `x`。

已定位的代码问题包括：

- BMP 的 RGB565 是低字节在前，旧显示器却按高字节在前组合，导致颜色错误。
- 旧显示器没有保留整条源扫描行，无法正确复制第二条显示行；新实现使用
  960 像素行缓存，将 960×540 精确放大到 1920×1080。
- 旧相册装载器以字节计数完成为显示条件，没有等待全部 DDR 写响应。
  新实现按 16 字节单词入队、锁存活动 AXI 数据，并统计成功 BRESP 后再换帧。
- 帧重置同时清除显示字节相位和预取状态，使用原始 LCD 时序对齐相册 FIFO。
- FAT32 无分区启动扇区的 454..457 字节不能作为分区地址；现在识别无分区
  BPB，并修正翻页边界、空相册以及失败状态重复报告的问题。

相册专项验证可单独运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/test-sd4.ps1 -GalleryOnly
```

覆盖完整 1920×1080 显示的像素、重复行、换帧和欠载恢复；64×8 原生 SD 卡
保存/读回，真实 AXI 控制器、两级仲裁、DDR 写响应到显示的完整通路；
首尾翻页、退出/重新进入，以及 SD CRC / DDR BRESP 错误后的单次回执和重试。
FIFO 模型按实际 `R0_FIFO_8` 的 `ENDIANESS=0`（高字节先出）配置。
