# image4：白背景上半身骨架试验版

image4 是独立工程：第一部分完成白背景分割、选区、掩膜细化和短枝清理；
本轮第二部分新增躯干主路径与双臂候选的结构约束。背景细节和进一步去影留作第三部分，尚未添加。
2026-10-22 串口改为上电静默；进入 U6 后每约 2 秒报告一次，退出 U6 停止自动报告，# 随时查询一次。
image3 保留原白布/背景差分、Canny 辅助与五类模板匹配，两者可以分别烧录对照。
本版从图像掩膜计算中心线，没有使用那五张模板，也没有按照固定身材比例放置关节点。

当前测试版按用户授权关闭 image4 的 N/2 弱前景补回：U3 的区域选择只接收强前景，
避免 N60 时差异 30～59 的相连背景被重新纳入。保留原去噪、连通区域选择、片段合并、
小孔洞修补和 16×16 块采样，因而 U3 不保证与 U2 逐像素相同。
串口版本仍为 V=4，默认 N 仍为 24，上板对照时需手动发送 N60 加回车。

测试顺序：烧录本次 checked.bit → V（回复 4）→ N60 加回车（回复 K）→ U2 → U3 → U4 → U6。
每次切换后等待完整快照更新，保持灯光、取景和人体姿势一致，观察原本在 U2 中消失的
相连暗背景是否还会在 U3 中出现；同时检查浅色手臂/衣服边缘是否更容易缺失。

当前同时保留原始二维形态骨架和结构筛选结果，后者最多保留一条躯干和每侧一条手臂路径，
带上一有效快照的软位置先验。尚未实现肩、肘、腕关节点、关节角度或动作分类，不发送 `POSE`。

## 下载和首次操作

工程：`images/image4_skeleton/Ti60_Image4_Skeleton.xml`。
JTAG 文件：`images/image4_skeleton/outflow/Ti60_Image4_Skeleton_checked.bit`。
本次仅本地编译，没有执行板上下载，也未重打包多镜像 Flash。

串口继续用 **115200、8N1、ASCII 文本发送，关闭 HEX 发送**。

1. 单独下载 image4 的 checked.bit，发送大写 `V`，应回复 `4`。
2. `C` 看彩色实时画面。镜头拍颈部以下到腰部，双臂和手留在画面内；白布铺满背景，
   画面四周留出可见白布。衣服和白布要有明显区别。上电自动使用白背景分割，无需 `b`。
3. `Q` 查询参考状态：`1` 表示白背景参考就绪，`0` 表示未就绪，`!` 表示处理错误。
   `Q=1` 仅说明参考可用，不代表已经找到人体或完成骨架。
4. 连续发送文本 `U3`，看选中人体的二值快照，应当主体为白色、布和投影尽量为黑色。
5. 发送 `U4` 看黑底白色骨架；`U5` 看同一快照的灰色人体掩膜与红色骨架。
6. `U6` 看约束后结果：绿色为躯干、青色为画面左臂、紫红色为画面右臂，灰色为同帧掩膜。
   没有可靠躯干时只显示灰色掩膜；缺一侧手臂时不补画。进入 U6 满约 2 秒后开始周期报告，
   `#` 可立即查询 `BODY`/`ARM` 字段。切换到 U4、U5、U0 或 C/G 即停止自动报告。
7. 缓慢伸开、上举或弯曲手臂，观察中心线是否随掩膜变化。骨架在完整快照处理后更新，
   不能按相机每帧输出速度判断它是否卡住。`C` 可随时返回实时彩色图像。

`U3` 是 **U 字节后紧接数字 3 字节**，不是单个特殊命令，无需回车。
只发 `U` 或 `u` 同样可以，大小写没有区别，每发一次依次切换：

- `0`：普通画面。
- `1`：原始白背景分割掩膜，实时诊断。
- `2`：去噪后的掩膜，实时诊断。
- `3`：实际送入骨架算法的选中人体快照，按 16×16 方块显示。
- `4`：骨架，正常收敛显示白色；达到迭代上限仍未收敛显示黄色。
- `5`：同快照灰色掩膜加红色原始骨架。
- `6`：同快照灰色掩膜加绿色躯干、青色画面左臂、紫红色画面右臂；之后再发 U 返回 0。

## 保留的控制

- `C`/`G`：普通彩色/灰度，退出掩膜显示。
- `U`/`u`：循环视图；`U0`～`U6` 或 `u0`～`u6`：直接选择视图。
- `N24` 再回车：设置分割差异阈值，范围 0～255，默认 24；回车回复 `K`。
- `D`/`d`：去噪模式循环 2→0→1→2，默认 2，回复当前模式。
- `F`：冻结切换，回复 `1` 冻结、`0` 实时；若画面静止，确保最后一次回复为 0。
- `Z`/`z`：HDMI 测试图开关；确保最后回复 0 才是在看摄像头。
- `I`/`J`：固定回复 `W`，说明当前入口为白背景分割。
- `Q`：查询参考/处理状态；`#`：任意视图均可查询一次骨架状态，不会开启自动报告。
- `U6`：开启结构约束视图及约 2 秒一次的状态报告，首次也等待约 2 秒；切换其他视图关闭自动报告。

ADC、模板匹配、Canny、RAW 背景缓存和 TF 功能在此镜像中关闭。
`E/T/A/H/L/R/+/-`、`X/O/S/M`、`b`、`%`、`~` 回复 `!`，避免进入没有硬件的模式。
白布和灰影抑制在 image4 中固定启用，不能用 `%` 切回原背景差分。

## 骨架串口状态

上电不主动发送骨架状态。只有进入 `U6` 后才每约 2 秒发送一行，首次同样等待约 2 秒；
无骨架时按相同周期报告 `SKEL:0`。有效/无效状态跳变不会额外插入报告。
退出 U6 后取消尚未发送的自动报告；已开始发送的一行会完整结束，避免截断。
`#` 在任何视图均可查询一次，包括尚无结果时；手动查询不启用周期发送。行尾 CR/LF，示例：

```text
SKEL:1 C:1 I:0A P:0030 E:0003 B:0001 R:0002 BODY:1 ARM:3
```

`SKEL` 表示有无有效区域的非空骨架；`C` 表示是否收敛。`I/P/E/B/R` 均为 **十六进制**：
`I` 是细化迭代数，`P` 是保留骨架像素数，`E` 是端点候选像素数，`B` 是分叉候选像素数，
`R` 是移除的短分支像素数。例如 `P:0030` 表示 48 个像素。
`B` 不是人体关节数，`SKEL:1` 也不是动作识别成功。
`BODY:1` 表示本快照存在可用的躯干路径；`ARM` 是两位标志：0 无臂、1 仅画面左臂、
2 仅画面右臂、3 双臂。这些是图结构候选，不能当作已经确认有人或识别出动作。
原 I/P/E/B/R 仍统计 U4 原始骨架，不是 U6 的像素数；尚未有结果时这些新字段为 0。

## 实现和范围

RAW 白背景估计、同色亮度/颜色比较、去噪及选区复用 image3 的必要模块。
私有 `image4_person_pipeline.v` 始终输出选中区域的二值像素，捕获不依赖当前显示视图。
整帧按正方形 16×16 像素 OR 汇聚为 **120×68**，末行保留剩余 8 个输入像素，
没有将上半身宽高各自拉伸。远处的人在此网格上分辨率低，应让上半身占据足够画面。

细化采用 Zhang–Suen 两个子迭代，读写使用独立 RAM，整个子迭代完成才换源。
最多 64 次迭代，达到上限仍发布带 `C:0` 标记的部分结果，不无限阻塞视频。
收敛后沿骨架追踪，移除长度最多 3 个网格像素的端点到分叉短枝，保留孤立线段；
追踪时去除可由正交路径替代的冗余对角连接，避免将普通拐角误作分叉。
只做一次清理扫描，较长杂枝不会被清理。

骨架、原掩膜和显示银行分开存储。两个显示银行只在垂直消隐期切换，
U5 不把旧骨架覆盖到另一个实时人体位置。处理忙时跳过新帧，相机和 HDMI 时序继续运行。
UART 使用带应答的数据邮箱跨时钟域，同一行发送过程中参数保持不变。
周期使能直接来自串口所在 clk_sys 域的 U6 请求，计时为 96 MHz × 2 秒，
无需跨域传递显示视图；退出时只清除自动请求，保留显式 # 查询。

手臂贴住躯干、两臂交叉、白衣与白布融为一体、浓重投影或布褶皱都可能使掩膜拓扑错误。
细化无法从缺失的轮廓恢复被遮挡的手臂；躯干也可能出现多余中心线。
U6 可以排除部分杂枝，但无法从错误的掩膜保证恢复正确人体。交叉、贴身或截断的手臂允许丢失；
屏幕左/右是按端点位置分组，并非人体解剖左右，交叉时尤其不能等同。

## 第二部分：结构约束

新增 `src/vision/upper_body_constraint.v`，处理顺序为：

1. 从掩膜包围框下三分之一统计各列支撑率，选出连续、稳定的躯干宽度候选。
2. 在该区域下半部找靠近中心、靠近底部的真实骨架点作为根，对其连通骨架进行八邻域 BFS。
3. 从靠近中轴的上端点沿父路径回到根，得到躯干路径；高度不足则整组拒绝。
4. 将外侧端点回溯到躯干，依据分支长度、上半段接入位置、跨中轴比例和上一结果的相对位置评分。
   每侧最多保留一条；两个候选共用同一出干枝时只保留得分更高的一侧。
5. 路径只使用“原始骨架 AND 原掩膜”的现有像素。没有可靠证据时不补画人体或关节。

所有比例基于当前躯干/包围框，不使用五张模板，也不固定一套身材。上一帧仅参与评分，
并随躯干平移补偿，不把旧骨架直接叠在新人体上。候选端点超过 32 个时拒绝结构结果，
原始 U4/U5 仍可查看；原始细化未收敛时也不输出结构路径。
120×68 的工作 RAM、原骨架显示和结构类别双显示银行分开，统一在消隐期切换。
计算较慢时跳过新输入帧，不暂停 HDMI 时序。

开源参考：[Skan](https://github.com/jni/skan)、[sknw](https://github.com/Image-Py/sknw)。
它们提供 Python 的骨架图、节点和路径分析，可以参考图分析方法；不是现成 Ti60 人体识别 IP，
也不直接给出人体肩肘腕。本版 RTL 是针对现有工程编写，没有移植其 Python 运行时或复制其源码。

第三部分的背景纹理判断和进一步去影暂不添加。原有白背景/灰影抑制保持之前配置。
