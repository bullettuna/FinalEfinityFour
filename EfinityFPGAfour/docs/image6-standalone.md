# image6：SD 自动加载与 HDMI 四点显示

本轮是临时 JTAG 下载版。SD 接线按用户最新确认仅完成接线，尚未实测；用户使用 2 GB FAT32 卡，稍后自行复制文件。本轮不写 SD 卡，不格式化卡，不写板载 Flash，不承诺断电后保留临时 FPGA 配置。

## 使用步骤

1. 先临时下载交付目录 `fpga/image6_sd_hdmi.bit`。不插卡或没有模型文件时，摄像头视频仍应运行，左上角显示启动错误；此时没有模型识别结果。
2. 用读卡器将交付目录 `sdcard/MODEL6.BIN` **作为普通文件复制到 FAT32 卡根目录**，保持名称。不要把旧 `model.bin` 改名替代，也不要把整个卡写成裸镜像；不需要安装程序或格式化。
3. 卡插好后重新临时下载位流，或在仍能加载本位流的配置条件下重新启动 FPGA。显示依次为 WAIT、LOAD、TEST、RDY。RDY 仅在 SD 校验和板上固定输入数值自检通过后出现。
4. 正常摄像头画面上显示双肩、双腕四个点及三条连线。无需开启电脑程序，无需 FT232H 接收。连线表示肩至腕，不代表检测了肘关节。
5. 玩电脑游戏时，关闭其他串口／FT232H 采图程序，在 PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File E:\Efinity_Project\FPGA_GAME\start-image6.ps1 -SkipDownload -ComPort COM30
```

新版默认检查板上 SD 启动、自检状态，然后开启 USB 坐标输出和游戏，不从电脑上传权重，不在电脑运行人体模型。点击开始游戏后，自然站立完成 15 个有效帧校准，再测试左右攻击、上跳、下蹲及同时攻击和躲避。游戏仍在电脑。

**临时下载后可以脱离电脑持续推理，但 FPGA 断电后需要重新下载位流。** 本轮没有改配置 Flash，也没有添加多镜像启动菜单。

## 文件与计算范围

`MODEL6.BIN` 共 235232 字节：64 字节包头、161440 字节冻结 INT16 权重、73728 字节固定自检输入。包头包括版本、长度、模型／输入／热图 CRC 和四点期望值，并校验包头 CRC。权重 CRC32 为 `bbffdf52`，模型结构和训练参数不变。

上电流程：等待 DDR 校准 → 初始化原生 SD 4-bit → FAT32 根目录查找 MODEL6.BIN → 校验每个扇区和包头 → 写权重及自检输入到 DDR → 校验文件内容 CRC → 在 FPGA 执行完整模型并对比四点和热图 CRC → 启动实时采样与推理。自检结果不会冒充实时人体点显示。

启动自检证明固定输入的数值计算一致，不代表真实场景识别准确率。没有模型文件就不会自动开始推理。SD 中的权重内容由用户稍后复制；软件和仿真不依赖当前实卡是否已经写好。

## 硬件与驱动依据

引脚、电平取自用户 `FT232H_硬件接入交接包_20261021.zip` 的最终资源清单。SD CLK、CMD、DAT0、DAT1、DAT2、DAT3 依次为 P4-27、28、33、34、25、26；FPGA 资源依次为 GPIOL_N_14、GPIOL_P_14、GPIOL_N_16、GPIOL_P_16、GPIOL_N_09、GPIOL_P_09，FPGA 端均为 1.8 V LVCMOS。模块侧 3.3 V 经已有板上电平转换，不把 image2 旧 3.3 V 引脚约束复制进来。

原生 `sd4_host` 和 `sd4_command` 直接复用 image2 当前实际调用链。初始化 400 kHz、运行 6 MHz，保留 SDSC 的 CMD16／字节寻址、SDHC 块寻址、CRC7／四路 CRC16、超时和错误处理。FAT32 文件读取参考 image2 流式解析，支持 MBR 中的 FAT32 主分区、无分区 FAT32，以及根目录和文件的 FAT 簇链；仅支持 512 字节扇区、FAT32、根目录 8.3 文件名，不支持 exFAT 或 FAT16。

文件数据先放在一个 512 字节缓冲，SD 扇区 CRC 通过后才向 DDR 提交。模型加载路径的 SD 写请求恒为零。image2、image5 和共用 SD／视频底层源文件不改动。

## 显示与 USB 行为

HDMI 默认是正常摄像头画面，Canny 继续供模型使用。四点通过握手及跨时钟同步传到显示域，在帧边界整组更新；Q14.2 的 640×360 坐标映射到 1920×1080。低分、越界和无效点不画，超过约 1 秒没有新结果时隐藏旧点。显示使用最近一次有效结果，不等待模型完成，也不把视频帧缓存排队来追齐模型延迟。

肩点颜色为青／黄，腕点为绿／粉。状态文字 WAIT 表示等待 DDR，LOAD 为读卡，TEST 为板上数值自检，RDY 为就绪，ERR 后跟十六进制错误码。

不连接 FT232H 时推理持续运行。电脑申请坐标流后，USB 数据包持有独立结果副本；USB 背压不会让推理等待，忙时跳过中间的 USB 结果。已有 UART 模式切换仍会先排空正在发送的数据，电脑控制脚本会在等待回复时持续读取 USB。

保留单字节 Z 的独立四色测试图，发送一次切入，再发送一次退出。C/G/E 仍可选择普通／灰度／边缘画面。这些查看命令不要求加载电脑模型。

## 错误定位

### 串口助手直接调试

使用 COM30、115200、8N1，ASCII 发送／接收，不附加回车换行。每次发送完整的三个字符，等本条回复结束再发下一条；下面命令仅适用于加入调试功能的新版位流。`~` 是英文半角波浪号，不是中文符号。

- `~6H`：显示命令提示。
- `~6S`：查询本次加载的 SD 初始化、FAT32 解析、启动阶段及错误。例：`SD INIT=1 FAT=1 STAGE=3 ERR=00 CMD=00 REASON=0`。
- `~6F`：查询 MODEL6.BIN 是否找到、目录文件长度、包头与内容 CRC，以及已读取的包字节数。正常为 `BIN FOUND=1 SIZE=000396E0 HDR=1 CRC=1 BYTES=000396E0`。
- `~6V`：查询模型就绪、板上数值自检、推理开关、当前忙状态、已完成实时计算次数与启动错误。正常启动后 `READY=1 TEST=1 ENABLE=1`；`BUSY` 在计算期间为 1、两次计算间可能为 0。
- `~6-`：关闭实时模型推理，回复 `MODEL OFF`。当前已经发出的 DDR／模型计算会安全完成，期间 `BUSY` 仍可能为 1；本次在途结果不再更新显示，四点在显示帧边界隐藏。摄像头视频和显示继续运行，不清除 DDR 中的权重。已经开始发送的 USB 数据包允许发完。
- `~6+`：打开实时模型推理，回复 `MODEL ON`；模型尚未就绪则回复 `MODEL NOT_READY`，不会跳过加载或自检。
- `~6R`：重新读取 SD、查找文件、校验并加载到 DDR，再执行完整模型固定输入自检。需先发送 `~6-`，查询 `~6V` 等到 `BUSY=0` 后再发。接受时回复 `SD RELOAD`，随后通过 `~6S`／`~6F`／`~6V` 查看进度。成功后保持关闭状态，再发 `~6+` 才恢复实时识别。

`~6R` 在开关未关闭时回复 `SD STOP_FIRST`；仍有计算／加载或 DDR 未就绪时回复 `SD BUSY`，稍后重试。查询结果是最近一次实际读卡／加载的状态快照，**查询本身不会重新读卡，也不能作为当前插卡检测**。更换或重新插入卡之后，应使用重新加载流程；若旧卡会话检查首次报错，关闭状态下重发 `~6R` 进行新的初始化。加载路径只读 SD，重新加载仅覆盖既有 DDR 模型／自检区域。

所有长度、计数和错误字段均用十六进制表示，`000396E0` 即十进制 235232 字节。`INIT=1` 仅说明 SD 主机初始化成功；`FOUND=1` 仅说明找到了目录项；`HDR=1 CRC=1` 说明包头与内容校验通过；必须再看到 `READY=1 TEST=1`，才说明完整模型固定输入数值自检通过。`CMD`／`REASON` 是 SD 主机最后一次失败命令及原因，`CMD=11` 表示十进制 CMD17；零表示本次没有记录到 SD 命令错误。

推荐现场验证顺序：发送 `~6S` → `~6F` → `~6V`；如需重新读卡，发送 `~6-` → 等 `~6V` 中 `BUSY=0` → `~6R` → 等 `STAGE=3` 且 `READY=1 TEST=1` → `~6+`。自动上电加载流程不变，正常使用无需串口命令。

这些开关是本次运行的状态，不写 SD 或 Flash；重新配置／复位后仍默认自动加载并开启。新命令不改变 MODEL6.BIN 的格式或权重内容，之前准备的同一启动文件可继续使用。关闭后 `RUNS` 允许在途计算再增加一次，后续应保持不变；重新开启后应继续增长。`ENABLE=1` 仅表示模型开关打开，旧 FT 手动模式和输入是否有效也影响实际运行；发送 `~6+` 可恢复独立自动推理，仍需摄像头提供有效输入。

若调试时手动关闭过模型，启动现有电脑游戏脚本前先发送 `~6+`。现有脚本负责 USB 坐标流，不覆盖本次新增的手动模型关闭状态。

- 01：SD 初始化失败。当前实卡／接线尚未验收，需现场核对原生 SD4 通信。
- 02：扇区读取或 CRC 失败。
- 03：不支持或不正确的 FAT32 引导／分区信息。
- 04：根目录未找到 MODEL6.BIN。
- 05：文件长度错误，常见于复制了原始 model.bin 或错误版本。
- 06：簇链错误或提前结束。
- 07：存储操作超时。
- 20：包头、模型版本或预期常量不匹配。
- 21：权重或自检输入 CRC 不符。
- 23：DDR 访问报告错误。
- 30：模型四点／热图 CRC 与固定输入期望不一致。

串口只读诊断：

```powershell
cd E:\Efinity_Project\FPGA_GAME
.\.venv-fourpoint\Scripts\python.exe .\image6_control.py diagnose --port COM30
```

返回 `standalone: true`；`boot_stage` 的 0／1／2／3／4 分别对应 WAIT／LOAD／TEST／RDY／ERR，`boot_error` 是错误码。录像链路计数仍可通过 HDL 工程 `tools/read-image6-video.ps1` 获取。串口助手、诊断脚本和游戏启动控制不可同时占用 COM30；多个接收程序也不可争用 FT232H。

## 构建与验证

准备启动文件：`python tools/prepare-image6-sd.py`，只写电脑目录 `tmp/image6_standalone/sdcard`。会生成与固件绑定的 `pose6_boot_identity.vh`，修改该文件后须重建位流。

回归入口：`test-image6-sd.ps1`、`test-image6-overlay.ps1`、`test-image6-standalone.ps1`、`test-image6-protocol.ps1`、`test-image6-video.ps1`。整链路仿真使用真实 SD4 主机／SDSC 卡模型、碎片 FAT32、实际 AXI 主机和内层仲裁、真实模型和完整 1080p/640×360 聚合路径；不通过伪造点位完成板上自检。

`test-image6-standalone.ps1 -WithVideo -SimulationName pose6_contended` 进一步接入实际外层 `photo_axi_mux`，持续调度 153.6 MB/s 读和 76.8 MB/s 写的视频模拟负载。当前调试版完成 65821 次读、32911 次写（每次 128 拍），最大请求至完成时间分别为 160／165 个系统时钟；串口关闭、缺失文件重载、恢复文件重载与重新开启全部通过。并发期间四次实时模型结果仍与整数参考一致，USB 阻塞及恢复后的数据包也通过生产解析器检查。这项测试覆盖仲裁与数据归属，不代替实际视频 FIFO、DDR PHY 或实板稳定性验收。

当前串口调试版构建使用 XLR 43285/60800、RAM 185/256、DSP 56/160，保留 Canny。全部 28 项建立／保持关系通过，96 MHz 系统建立裕量 0.176 ns。重量化乘法保留流水级；500 项算术边界和十层卷积全部输出与原整数参考一致。电脑端代码未修改，既有 40 项回归及游戏状态测试通过。

`build-image6.ps1` 检查完整构建、源文件指纹、建立／保持时序、引脚和映射资源。`package-image6-standalone.py` 只在所需回归与构建合格时打包。交付 manifest 保存位流、启动文件、源提交和报告校验值。

构建和仿真通过不等于实板验收完成。实卡读取、长期 HDMI 稳定性、实际帧率和跨人动作效果仍需用户复制文件、临时下载后现场验证。没有访问 USB／JTAG／串口硬件，没有向 SD 或 Flash 写入数据。
