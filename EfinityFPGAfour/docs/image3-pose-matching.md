# image3 V9：差分人体与五类姿态匹配

当前参考已替换为[实拍上半身掩膜模板](image3-photo-templates.md)，`V` 回复 `P`；以下为原V9阶段记录。

当前已按用户确认改为 [上半身匹配版](image3-upper-body.md)，V 回复 `U`，
无需头和腿入镜；以下为原 V9 全身版的架构、操作与阶段验证记录。

本版在 image3 中接入 C++ 的五类**填充轮廓**匹配，使用对应快照的真实 Canny 作辅助确认。
结果通过 UART 输出；HDMI 保留 C/G/E 和 U0～U6 的原有画面，本版没有增加骨架或姿态文字叠加。
ADC 保持关闭，Canny 上电及 R 复位阈值仍为用户要求的 0/0，N 差分阈值默认 24。

## 理想工作过程与使用

1. 固定摄像头，画面中先没有人；发送小写 `b` 采集背景，通过 `Q` 等待回复 `1`（背景已准备好）。
2. 人完整进入画面，单人在背景前做五种模板之一的姿态并短暂停留。
3. 差分、去噪、片段合并和小孔修补产生人体填充掩膜；U3 可查看人体掩膜，U5 查看 ROI，U6 查看 ROI 内 Canny。
4. 后台归一化人体，得到匹配编号；连续三个**完成的快照**得到同一编号才确认。
5. 姿态变化后串口发送一行，例如 `POSE:3 SCORE:0720 GAP:0120 E:0450`；同一姿态不周期刷屏。
6. 单独发送 `#` 查询最近确认的姿态及最近一次该姿态的分数。`POSE:0` 表示未知/丢失/不满足确认条件。
   分数在等待三次确认期间保留上一个稳定结果；未知样本会立即清除已确认姿态。
7. 大写 `V` 回复 `9`，用于区分此前 V8 的纯 R 优化版。串口仍为 115200 / 8N1，单字符不需回车。

SCORE、GAP、E 均为 0～1000 的千分制数值；例如 SCORE=720 是 72.0% 轮廓交并比，**不是识别正确率**。
识别更新依赖快照处理完成，不等于每秒识别 60 次；忙碌时跳过输入帧，HDMI 不等待匹配模块。

## 判定规则

- 主判据：选中并修补后的人体填充掩膜，与 5 个 C++ 模板的前景 IoU。
- 使用最终掩膜重新测出的紧边界，不能使用显示框的 PAD 扩边和平滑结果。
- 归一化与 C++ 一致：64×64，源坐标 `min + floor((2*i+1)*crop_size/128)`。
- 各模板分数 `floor((1000*intersection + union/2)/union)`；第一名至少 550，领先第二名至少 80。
  同分时保留 C++ 的低编号优先规则；不足差距仍拒识。
- 辅助判据：在第一名模板的边界位置，统计同一人体快照的 Canny 覆盖率 E，至少 200 才接受。
  200 是本版待实拍校准的初值，不是已验证的准确率指标；目前没有采用未校准的加权融合分数。
- 掩膜为空、边缘帧标签不完整、配置/背景失效或边缘支持不足均输出未知。

两条数据路径共用坐标和帧 epoch 校验：16 行 Canny 环形缓存先对齐延迟的 RAW 差分，
在同一次人体捕获期间将 Canny 按 8×8 OR 保存为 240×135 二值快照。
该边缘快照保持到人体离线处理及匹配结束，随后才能重新捕获；不会将旧人体与新实时边缘混用。
实际边缘会受衣服纹理、光照和阈值影响，粗网格 OR 提供空间容差，也可能降低辅助判据的区分度。

匹配复用 selected 后台 RAM 的既有处理读口，前台显示读口保持独立。
捕获期间不匹配，匹配完成后再发布后台掩膜；不增加 selected RAM 的第三个读口。
Canny 阈值、白平衡、Gamma、N/去噪设置或背景失效时，取消相关未完成任务并清除旧识别结果。

## 代码与模板来源

- `src/vision/person_pose_matcher.v`：归一化地址、五路交并集计数、共享逐位除法、排名、边缘确认。
- `src/vision/person_snapshot_selector.v`：最终紧边界、冻结边缘、后台 RAM 读口与匹配任务。
- `src/vision/person_roi_pipeline.v`、`person_canny_roi_view.v`：帧/行标签与 RAW、边缘、诊断显示的像素延迟对齐。
- `src/vision/person_pose_uart.v`：三次确认、带确认握手的跨时钟邮箱、变化报告与 # 查询。
- `src/vision/pose_templates.vh`：五类填充模板及边界 ROM，包含明确的初始化常量，无运行时外部文件依赖。
- `tools/export-pose-templates.py`：读取 C++ 项目 `samples/pose1..5.pgm`，按暗色阈值 127、8 连通最大区域、紧框和 64×64 规则导出。
- `pose-template-manifest.json`：五张来源 PGM 的 SHA256 与归一化前景/边界数量。

模板来自 `E:/vscode/cpp/EfinityFour` 的原有样本，C++ 项目源文件没有被修改。
可使用 `python tools/export-pose-templates.py <CPP目录>/samples --check` 检查模板是否与来源一致。

## 验证

运行 `tools/test-person-pose.ps1 -CppRoot <CPP目录>`。
测试工具编译原 C++ 源码的测试入口作为独立参照，直接调用原 `identify_pose`，核对 18 组输入的
每个模板交集/并集/整数分数、最终编号和差距，包含五个模板、方块、空掩膜、混合姿态、孔洞、
平移裁剪、8×6/2×3 小区域、缺少边缘和无效边缘帧。另检查任务取消。

还包括异步 UART 邮箱和忙碌时更新、三快照确认、查询/不重复、人物丢失，
selector 后台快照配对与紧框，以及 RAW→差分→形态学→行缓存→快照→匹配的完整集成测试。
完整集成测试同时验证 U1 像素位置没有因新增对齐延迟而移动。
既有 R 修补、0/0 串口阈值、人体显示和 1080p Canny 行缓存也需通过回归。

Efinity 对仅初始化、没有运行时写口的 `template_rom` 会给出“无驱动”提示。
构建检查仅对此精确对象采用附带实证的 ROM 检查：`tools/check-pose-rom.py`
逐位解码实际映射的五块 RAM10 的全部 40960 个 INIT 位，核对模板、地址、输出位段、时钟、读延迟及写禁用。
任意初始化位损坏或缺少 ROM 都必须拒绝；其他应用无驱动警告仍会拦截构建。

五个模板的自测通过只说明移植一致性，不能作为真实人物识别率。
理想场景是固定机位、单人、人体完整、背景稳定、轮廓与模板较接近；
仍需实拍五类姿态及非模板姿态，校准 IoU、差距和边缘覆盖阈值。
本版不是通用人体关键点检测，也没有移植 C++ 游戏碰撞。
