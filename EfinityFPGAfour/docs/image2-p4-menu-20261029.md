# image2：P4 硬件与按键功能窗口

新版工程：`images/image2_p4_menu/Ti60_Image2_P4_Menu.xml`。
旧版 `images/image2_photo` 的源码、P3 约束、BIT 和 HEX 保留用于回退；
`tools/build-image.ps1 -Image 2` 从本版起调用新版 P4 构建脚本。
image1、5、6、7 的运行源码和既有发布文件不变。

## 硬件配置

依据用户提供的 `FT232H_硬件接入交接包_20261021/01_FPGA最终引脚表.csv`，
并复用已用在 image1 的 P4 焊盘配置。以下 13 路 FPGA IO 均为 1.8 V LVCMOS；
扩展板外围侧的 3.3V 与 FPGA 引脚电平是两回事。

- ADC：SCLK G4、MOSI G3、MISO G2、CS H2。
- OLED 保持空闲：CS F5 拉高，DC G5；本版不增加 OLED 显示程序。
- SD 原生四位：CLK F2、CMD F1、DAT0 C1、DAT1 D1、DAT2 G1、DAT3 H1。
- SW1：A2，低电平有效；SW2、SW3 继续通过 MCP3202 CH1 电阻键读取。
- CH0 为旋钮；SPI Mode 0 / 500kHz，原 ADC 滤波、按键窗口、死区和消抖保留。

相机、HDMI、DDR、UART 引脚和 PLL 频率保持原 image2 配置。
SD 沿用原生 SD4 驱动：初始化约400kHz、运行约6MHz，保留 SDSC／SDHC 和 FAT32。
P3 上原 ADC／SD 输出已从新版引脚约束移走。image2 沿用 UART 收图，
未增加 FT232H 图像发送算法；接入新硬件不等于启用每个硬件外设。

## 按键操作

1. 长按 SW1 约0.8秒打开／关闭窗口。
2. 浏览时，SW2 上一项、SW3 下一项；旋钮也可滚动。
3. 短按 SW1 切换开关、模式或执行动作。
4. 数值项短按 SW1 进入编辑；SW2 加一、SW3 减一，旋钮粗调；再短按 SW1 确认。
5. 旋钮只在窗口中滚动或编辑选定项；关闭窗口后不直接接管阈值，避免上电位置覆盖 H/L 默认值。

22项菜单依次为：VIEW、SAVE SD、GALLERY、FREEZE、TEST、CANNY、CANNY H、CANNY L、
CANNY RST、MEDIAN、WB R／G／B、WB RST、GAMMA、GAMMA P、CLEANUP、MIN AREA、
CHECK SD、PREV BMP、NEXT BMP、DELETE BMP。

- VIEW 只循环 COLOR／GRAY／EDGE，与 image2 三种照片算法一致。
- SAVE SD 拍照、处理并保存 RGB565 BMP；GRAY／EDGE 保存成功后自动打开刚保存的照片。
  彩色照片保存后仍保持实时画面，可通过 GALLERY 打开。
- GALLERY 进入／退出相册；PREV／NEXT 翻页，底部显示当前七位文件编号。
- DELETE BMP 第一次按下后提示 PRESS AGAIN；在原五秒确认窗口内再按一次才删除。
  确认提示以原存储状态机允许确认为准；未打开可用照片、忙碌或导航后不会直接删除。
- CLEANUP 为0／1／2，MIN AREA 为0～2047，沿用原照片完整八连通处理。
  实时预览与照片完整处理的尺度及去斑效果依然不同。
- CHECK SD 显示 UNCHECK／WAIT／PASS／FAIL。PASS 表示原生 SD 初始化完成，
  **不是 FAT32 文件系统写入测试**；拍照和相册读取用于检验文件层。
  FAIL 行附带 CMD 十六进制命令号和 R 原 SD 错误原因码；结果持续显示，
  不会因为一次忙碌拒绝就显示成功。
- 底部状态来自实际存储事件：拍照、处理、保存、相册、失败、忙碌和删除确认。
  S 是当前处理阶段的十六进制编号，E 是最近事件附带的两位十六进制代码。
  SD 失败的详细原因同时保留在 CHECK SD 行。
- 本版没有模型 BIN 加载功能，也没有模型推理／骨架选项。

原 UART 115200／8N1 命令和图像导出包保持兼容：C/G/E、H/L/R、WR/WG/WB/WD、Y/P、M、
D/N、b存卡、i查卡、x相册、<和>翻页、d双确认删除、@串口收图等仍可用。
面板和串口写同一组实际寄存器；同周期冲突时面板选定项优先。
原默认参数保留：上电彩色、H60/L30、WB335/248/280、Gamma开启／42、中值开启、
CLEANUP1、MIN AREA20；没有套用 image5／7 的 H23。

## 工程与发布

```powershell
& tools/build-image.ps1 -Image 2
& tools/test-image2-p4-menu.ps1
```

构建脚本重新生成 P4 外围约束，保留原时钟关系，并加入与稳定 image7 一致的
MIPI setup 0.5ns／hold 0.3ns 额外余量要求；未改变相机数据采样 tap 或时钟频率。
只有全部 setup／hold 关系非负、CDC 检查、生成引脚表和实际网表资源检查通过后，
才生成 `_checked.bit`／`_checked.hex` 和资格报告。

本版是独立 image2 下载文件，没有重打包当前 Flash 内的7／1／5地址表。
先用 JTAG 临时下载验证；它不会自动出现在原 BOOT IMAGE 菜单中。
软件验证与实板验证分开记录，未经过实际板卡测试的构建不宣称已上板成功。

窗口沿用原文本渲染器的三拍同步流水线，状态记录在系统域产生并在消隐期提交至像素域。
独立复制的 `image2_photo_pipeline.v` 仅增加状态输出，没有修改 SD／FAT32／DDR
拍照、失败重试、自动预览和删除状态机；检查脚本自动比较其归一化内容。

## 本次验证结果

2026-10-29，Efinity 2025.2.288 / Ti60F225 C4 / TIMING_2 / effort2 / seed4：
全部28项 setup／hold 关系非负，CDC无 synchronizer 警告。
系统域 setup/hold 为 +1.941/+0.026ns，像素域 +1.255/+0.026ns，
摄像头域 +1.905/+0.019ns，后者已经计入额外 setup0.5ns／hold0.3ns 余量。
最小受约束关系余量为 +0.019ns。此结论限于工具时序模型，未测量实板外围信号。

实际资源为 XLR 38,371/60,800（63.11%）、RAM10 127/256（49.61%）、
DSP 32/160（20%）。生成引脚表逐路校对13路 P4 焊球、电平和方向，
其余外围配置与原 image2 相同；网表检查未发现新增应用信号未驱动、锁存或多驱动问题。

已通过：真实菜单控制寄存器和数值边界、C/G/E循环、原UART命令兼容、
窗口开关时逐像素检查三拍 VS/HS/DE/RGB 对齐、完整窗口截图检查；
真实按键菜单到原生 SDSC SD4、完整 Canny、FAT32 BMP 存储、自动预览和双确认删除，
并与真实视频DDR调度和两级AXI仲裁并发运行。上述存储集成使用缩小画幅，
不代替实板1080p带宽和真实SD卡兼容性测试。

额外注入CMD9回复CRC错误，检查窗口实际显示 FAIL、CMD09／R2；
恢复正常回复后重新查卡，窗口显示 PASS，后续存卡／删除正常。
修复了新接入的相册状态在嵌套 generate 作用域中被隐式声明为未驱动局部信号的问题。
原127份BIT／HEX及除构建入口和忽略规则外的800份既有受跟踪文件均保持原字节。
本轮未连接串口、JTAG、SD读卡器，未下载、未烧写Flash。
